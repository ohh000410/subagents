# 범례를 축 안 빈 자리에 놓기

## 절차 (검증됨)

1. **빈 자리는 격자 탐색으로 찾음.** 네 모서리만 보면 부족.
   범례 크기(축 단위 환산)의 창을 축 안쪽 전 영역에 26×26 격자로 훑어 데이터 점유
   최소점을 선택. 곡선은 꼭짓점만 세지 말고 선분을 조밀 샘플링(densify)해서 셈.

2. **배치는 페이지 좌표(`legend.left`/`legend.top`)로 함.** `legend.x`/`legend.y`
   (축 좌표)는 **앵커 기준이 일관되지 않았음**: 같은 스크립트에서 Graph6 은 y 값이
   범례 아래쪽 기준으로, Graph2 는 위쪽 기준으로 동작해 프레임 위로 삐져나갔음.
   레이어 페이지 사각형(`layer.left/top/width/height` × `page.width/height`)을 읽어
   축좌표 → 페이지좌표로 직접 환산하면 모호성이 없음 (`legend.top` = 위 모서리 확정).

   ```python
   left_pg = Lx + (bx - xf) / (xt - xf) * Lw
   top_pg  = Ly + (yt - by) / (yt - yf) * Lh    # 축 y 는 위가 크고 페이지 y 는 아래가 크다
   ```

   `legend.left/top/width/height` 와 `page.width/height` 는 같은 절대 page unit 이고, `layer.left/top/width/height` 는
   페이지 대비 퍼센트(0~100). 먼저 `Lw = layer.width/100*page.width` 로 환산한 뒤 섞음 — 안 하면 탐색 상자가
   약 40배로 커져 "빈 자리 없음"이 나옴. 단위를 미리 알려 주는 속성은 없음(교정 png 의 종횡비로 확인).

3. **프레임·눈금에서 떨어뜨림.** 격자 탐색 후보에서 범례 상자가 레이어 프레임 안쪽 여백
   (레이어 폭·높이의 **4% 이상**)을 침범하는 셀은 제외. 점유 0 이어도 프레임에 붙은 자리는
   답이 아님 — 점유 0 셀을 골랐는데 범례 스와치가 왼쪽 축선에 겹쳐 렌더된 실측이 있음.
   곡선 점유 계산에도 프레임·눈금 라인을 점유로 넣음.
   점유 0 인 상자도 곡선에 접하기만 하면 렌더에서 닿음. 점유를 셀 때 검사 영역을 사방으로 부풀리되
   범례 상자 자체는 그대로 둠 — 축 범위의 3 % 는 부족했고(링 검사에서 곡선 픽셀 약 44개) 5 % 에서 0개가 됐음.
   5 % 는 시작값이고, 곡선이 촘촘하면 그래프마다 다시 검증.
   **점유 0 셀이 여럿이면 가장 먼 자리를 선택** — 각 후보에서 곡선·프레임까지의 최소 거리를 재고
   그 최소 거리가 가장 큰 셀을 택함.

4. **렌더 후 픽셀로 검증.** export png 에서 `legend.left/top/width/height` 를 픽셀로 환산해
   그 상자를 여백만큼 키운 영역 안에 곡선·축선 색 픽셀이 있으면 실패 — 다음 후보 셀로 옮겨
   재렌더. 범례 자신의 글자와 견본선 안티에일리어싱이 `legend.width/height` 상자 밖으로 몇 px 번지므로,
   링 검사는 상자 ±8 px 를 범례 내부로 제외하고 링은 실제 상자 가장자리에서 바깥으로 측정(안 그러면 범례
   자신이 곡선으로 검출됨, 약 44 px). 일부러 곡선 위에 둔 상자로 음성 대조를 해서 검사기가 잡는지 확인
   (실측 971 px).

5. `legend.background=0` 은 **`legend.left/top` 보다 먼저** 설정. 뒤에 주면 반환값은 True 인데 위치가
   기본 위치만큼(+23,+24 page unit) 밀려 저장됨.
   위치는 `verify(app, intended)` 의 `intended["legend"]` 로 되읽어 확인됨.

## ★ 함정 (실측)

- **`legendupdate;` 는 범례를 재생성.** 맞춤 `legend.text$` 가 있는 그래프에서
  위치만 옮기려고 부르면 내용이 날아가고 밴드·기준선까지 항목으로 붙음
  (`K` `L` `N` `O` `Q` 같은 쓰레기 항목이 붙은 실측). 위치만 바꿀 때는 부르지 마라.
  범례 크기를 읽어야 하는데 맞춤 범례가 있다면: text$ 를 백업 → legendupdate →
  text$ 복원 순이 아니라, **그냥 legendupdate 없이 legend.width/height 를 읽으면 됨**
  (이미 존재하는 오브젝트라 값이 나옴).

- **`%(n)` 참조로 범례를 만들면 컬럼 Long Name 이 통째로 딸려옴** (한글·수치 포함).
  영어 전용 규칙 하에서는 **리터럴 이름을 직접 넣음**: `\l(6) Sample 1` 식.
  구분자는 진짜 개행 `"\n"` — `"\\n"` 로 이스케이프하면 리터럴 'n' 이 찍힘(실측).
  열 Long Name 이 이미 짧은 영어이면 기본 자동 범례가 그 이름 그대로 나옴 — 이때는 수동 구성을 건너뛰고
  `legendupdate;` 로 크기를 읽어 바로 배치. 수동 구성은 Long Name 에 한글·단위·수치가 있을 때만 필요.

- 범례를 안으로 옮긴 뒤 **아래에 남는 옛 범례 자리(빈 여백)를 회수**:
  `page.height = xb.top + xb.height + 60` 으로 줄이고 `layer.top/height` 는 절대값
  보존으로 재환산. geometry 를 먼저 전부 끝낸 뒤에 범례를 측정·배치할 것
  (속성이 한 단계 늦게 반영됨 — `page_and_axes.md` 「기하 쓰기 순서」).
