# PPT 3D — 투영 모델 · 단차 · 그룹 · 구멍

**재현·창작 양쪽에서 다 씀.** 열거표·enum·속성 대응은 `pptx_api_dict.md`.

### ★ 구멍 뚫기 (배경색으로 덮는 것과 다름)

배경색 폴리곤으로 덮으면 배경을 바꾸는 순간 그 자국만 남음. 실제로 뚫으려면
`<a:custGeom>` 의 **같은 `<a:path>` 안에 서브패스를 하나 더** 넣고 바깥과 **반대
방향(winding)** 으로 감음.

```python
path = spPr.find(qn('a:custGeom')).find(qn('a:pathLst'))[0]   # 기존 path 를 재사용
q = [(emu(X(x)) - shape.left, emu(Y(y)) - shape.top) for x, y in hole]   # 로컬 EMU
if sign(shoelace(q)) == sign(shoelace(outer)):
    q = q[::-1]                                    # 반대로 감아야 구멍이 된다
path.append(parse_xml('<a:moveTo %s><a:pt x="%d" y="%d"/></a:moveTo>' % ...))
# lnTo 들 ... 마지막에 <a:close/>
```

⚠️ **`<a:path>` 를 하나 더 만들면 구멍이 아니라 그냥 덧칠됨.** PowerPoint 의
Merge Shapes ▸ Subtract 결과 XML 도 path 는 하나이고 그 안에 `moveTo…close` 쌍이
둘이며, 안쪽 쌍의 방향이 반대.

**검증**: 배경 사각형을 다른 색(예: `FF00FF`)으로 바꿔 렌더. 구멍 안이 그 색으로
따라오면 진짜 구멍이고, 원래 배경색 그대로면 덮은 것.


### ★ 투영 모델 — 각도를 더듬지 말고 역산

⚠️ **`rms` 를 믿기 전에 `FieldOfView` 가 70 도 아래인지 확인.** 높은 fov 에서는
원근 나눗셈 `1/(1-z'/D)` 가 폭주해서 잔차와 실제 렌더 오차의 상관이 뒤집힘:

| fov | 1.0 | 48.1 | 54.0 | 64.9 | **80.0** | 83.5 | 100.8 |
|---|---|---|---|---|---|---|---|
| 실제 렌더 코너 오차 (px) | 2.1 | 4.0 | 3.0 | 5.0 | **14.2** | 18.1 | 55.3 |

같은 요소의 세 해를 실제로 렌더해 잰 값 — **모델이 완벽하다고 평가한 해가 실제로는 가장 나빴음**:

| 해 | fov | 모델 rms | **실제 렌더 RMS** |
|---|---|---|---|
| 이웃과 카메라 일치 | 64.9 | 0.00 | **3.69** |
| 꼭짓점 하나를 추정 | 83.5 | 3.56 | 10.80 |
| 실측점만 정확히 맞춤 | 100.8 | **0.00** | **32.01** (앞 꼭짓점 55 px) |

오차는 뷰어에 가장 가까운 앞 꼭짓점에 몰림. fov 하한(1.0)에 붙는다고 안전한 게 아님 — 얕은 윗면에서는 RotY ≈ −87° + 거대한 plan 인 축퇴 가지로 넘어가고 rms 는 양쪽 다 0. `solve_3d` 의 `PLAN_MAX_RATIO` 가드가 검출(`snippets/pptx_frame.py` ★★★).
★ `solve_3d` 는 fov > 70(`FOV_MAX`) 이면 **예외를 던짐**. 잔차를 낮추려 하지 말고
**조건을 하나 더 넣음.**

**자유도**: 꼭짓점 하나가 가려져 실측이 3개뿐이면 방정식 6개에 미지수 7개(RotX·Y·Z·fov·W·cx·cy)
— 1-매개변수 해 다발이라 rms 0 은 공짜로 나오고, 최적화기는 fov 쪽으로 미끄러짐.
- 추정 꼭짓점을 데이터인 척 넣지 않음 — 제약 비용이 실측 꼭짓점으로 몰림(17 px 실측).
- 추정 꼭짓점을 **자유변수로 두고**, 다발 중에서 **이웃 요소와 카메라가 맞는 것** 선택.
  폭발도의 층들은 대체로 같은 카메라 공유.
- 크기는 다발 위에서 거의 안 변함(세 해의 W 4.0330 / 4.0332 / 4.0334). **치수는 믿고, 카메라는 못 믿음.**

구현: **`snippets/pptx_frame.py`** (`solve_3d` · `unproject3d`). 캘리브레이션 216점 +
가설 48개(회전순서 6 × 축부호 8) 탐색으로 확정, **학습 RMS 3.14 px · 홀드아웃(20%) 3.50 px.**

```
p  = (±W/2, ±H/2, z)          원본 사각형 꼭짓점 (인치).  돌출면은 z = -Depth_pt/72 (뒤로)
p' = R · p                     R = Rz · Rx · Ry  (순서 ZXY), 부호 (RotX +, RotY -, RotZ +)
D  = 1.1337 · max(W,H) / tan(fov/2) + 2.8498
화면px = (cx, cy) + k·(x', y') / (1 - z'/D)      k = 0.99166 · (렌더폭px / 슬라이드폭in), x·y 동일
```

★ **축이 통상 규약과 반대.** 단일축 실측:

```
RotationY -45  ->  세로비 0.710 (= cos45)     RotationY = 화면 가로축 회전(pitch)
RotationX  45  ->  가로비 0.709               RotationX = 화면 세로축 회전(yaw)
```

**역산** (`frame.solve_3d`): 목표 윗면 꼭짓점 4개 + 두께 → `RotX/Y/Z, fov, W, H, Depth, 위치`.
`least_squares` 한 번, 렌더 불필요. 구멍 위치는 `frame.unproject3d` 로 화면 좌표를 원본
평면(z=0)으로 되돌려 얻음. 교정 범위(rx≤70·rz≥-60·fov 30/55/80, 사용 상한 70) 밖 외삽이면 잔차 ~10px 이 남음.

**세 손잡이 — 목표 투영에 맞추는 법**

| 맞출 것 | 손잡이 | 실측 |
|---|---|---|
| 마름모 시점 | `rev`(RotZ) | **0 이면 절대 안 나옴.** 등각 프리셋은 ±60 |
| ★ 전부 한 번에 | **`frame.solve_3d()`** | 위 모델로 역산. 아래 손잡이는 감을 잡을 때만 |
| 뒤:앞 높이비 | `perspective*` + `fov` | fov 80→1.00, 110→0.86, 140→0.59 |
| 전체 벌어짐 | `RotationX`(기울기) — **키울수록 납작해짐** | 45→(뒤+앞)408 · 60→278 · 70→194 · 20→594 |
| 〃 (보조) | 원본 사각형 **세로/가로비** | 1.00→0.607, 0.60→0.475, 0.40→0.372, 0.28→0.301 |
| ⚠️ 셋이 얽힘 | 원근에서는 도형이 커지면 더 벌어짐 | W·fov·RotX 를 따로 못 맞춤 → 격자 탐색 |
| 두께 | `extrusionH` | 선형 |

**구멍**: 구멍 뚫린 윤곽에 `sp3d` 를 주면 안쪽 벽이 자동 생성됨. 위에서 보면 먼 쪽 벽이
어두운 ⌄ 두 줄로 보이고 그 사이로 뒤가 비침.


### ★★ 투영 계열이 둘 — 축측 vs 사투상 (2026-09-05 실측)

`solve_3d` 는 **축측(axonometric)** 만 다룸.

| | 축측 (axonometric) | 사투상 (oblique) |
|---|---|---|
| 언제 나오나 | **`Rotation*` 중 하나라도 0 이 아니면 무조건** | **회전을 아예 안 주면** 프리셋 그대로 |
| 앞면 | 회전만큼 단축 | **무왜곡** (깊이를 키워도 앞면 크기 불변) |
| 세로 모서리 | `rev=0` 이면 수직 | 수직 |
| **밑변** | **피치가 있으면 V 자로 꺾임 (불가피)** | **수평** |
| 깊이 | 세 축이 함께 단축 | **45° 전단, 깊이에 선형** (`offset ≈ 0.354·D`) |

`Rotation` 을 **0 으로 «명시»** 하는 것은 괜찮음 — 사투상이 유지됨.

**프리셋별 실측** (같은 상자, 한 렌더에서 12종 비교. 앞면 윗변 기울기 0 = 사투상)

```
prst                       밑변    앞면:옆면   윗변기울기
26 + Rotation(44,13,0)     V       108:46      -0.218    ← 축측
isometricTopUp(20)         V       195:75      +0.404    ← 축측, 세로도 기움
legacyObliqueTopLeft(1)    flat    150:23       0.000    ← 사투상
legacyObliqueTopRight      flat    151:23       0.000       전단 +0.356·D (오른쪽)
obliqueTopLeft(40)         flat    151: -       0.000       전단 0.212·D
obliqueLeft(43)            flat    150:20       0.000       전단 수평만 (지붕 없음)
orthographicFront          flat    151: 0       0.000
```

**어느 쪽을 쓸지**
- **장면에 지평선이 있으면 사투상.** 지면에 선 물체는 밑변이 수평이어야 함.
  축측을 쓰면 밑변이 V 자로 꺾여 «떠 있는 도미노»가 됨.
- **물체 하나를 돌려 보여줄 거면 축측** (`solve_3d` 로 역산).

**전단 방향이 카메라 높이를 정함.** `*Top*` 계열은 윗면이 보이고(내려다봄), `*Bottom*` 계열은
밑면이 보임. `scene3d` 는 도형마다 붙으므로, 꼭대기가 지평선 위인 물체는 bottom, 아래인
물체는 top 으로 갈라 주면 눈높이 원근을 근사할 수 있음.

⚠️ **`prst` 문자열은 판정 근거가 못 됨.** `<a:rot>` 이 있으면 rot 이 이기고,
**`Shapes.Range(...).Group()` 이 그룹 안 도형의 `prst` 를 통째로 재작성** (rot·렌더는 그대로).
되읽기로 검증되지 않는 항목이므로 렌더 실측(밑변 꺾임·앞면 윗변 기울기)으로만 판정.

**원근(perspective) 계열은 규칙이 또 다름**

| | 사투상 | 원근 |
|---|---|---|
| 명시 회전을 주면 | 축측으로 재분류 | **재분류 안 됨** (prst·fov 유지) |
| `Rotation 0,0,0` 명시 | 시점 유지 | **프리셋 고유 시점이 지워져 정면 평면**이 됨 |

`perspectiveLeft/Right` 만 세로 수직 + 지붕 미노출 유지. `fov` 를 키우면 옆면 윗변에
기울기가 생김 (fov 15→0.075, 45→0.189, 105→**0.514**, 120→1.099).

### ★★ «지평선이 밑변에 있는 2점 투시» 를 3D 설정만으로 만드는 법

- `RotationY`(피치)를 0 으로 박으면 요를 55°까지 줘도 지붕·밑면 노출이 **전 셀 0%**.
  원근 카메라가 bbox **중심**을 보므로 피치 0 이면 카메라가 상자 중간 높이에 있음.
- `V/앞면기울기` 는 요에만 의존하는 상수(y45 90 · y55 75). 단 **밑변을 그린다는 전제**에서만 제약.

**해법 — 상자를 2배 높이로 만들고 아래 절반을 지면으로 덮음.**
상자를 `2H` 로 만들고 아래 `H` 를 가리면 보이는 밑변이 정확히 카메라 높이에 위치 →
지평선 위로 투영되니 **V = 0**. 밑변 제약이 사라지면 `fov` 를 올릴 수 있고 윗변 기울기가 목표에 닿음.

```python
# 상자는 2H 로 그리고, 같은 슬라이드에 배경색 사각형을 «나중에» 얹어 아래 절반을 덮는다
# frame(snippets/pptx_frame.py) 의 emu·rgb·PT 를 import 한다
from pptx.enum.shapes import MSO_SHAPE
def rect(sh, x, y, w, h, fill, name):          # 인치. prstGeom 필수(2H 트릭) — poly()(custGeom) 로 바꾸지 않는다
    s = sh.add_shape(MSO_SHAPE.RECTANGLE, emu(x), emu(y), emu(w), emu(h))
    s.fill.solid(); s.fill.fore_color.rgb = rgb(fill)
    s.line.fill.background(); s.shadow.inherit = False; s.name = name
    return s
rect(sh, cx - W/2, cy - H2/2, W, H2, FRONT, "bldg")   # H2 = 2 x 보이는높이
cfg = dict(PresetCamera=50,            # perspectiveRight
           FieldOfView=105.0,
           RotationX=47.5, RotationY=0.0, RotationZ=0.0,   # 피치 0 이 핵심
           Depth=PT(90), ExtrusionColor=0x6E6E6E)   # COM 색은 BGR: (b<<16)|(g<<8)|r (회색은 같음)
rect(sh, cx - CW/2, cy, CW, GROUND_H, BG, "ground")   # 아래 절반 덮기
```

**검량선** (W120 D90, `perspectiveRight`, 피치 0, 밑변 V 는 전 조합 0):

```
                 옆면윗변  앞면윗변   비
  H460 y45 f105   0.464    0.395    0.85
  H490 y47 f105   0.457    0.452    0.99
  H501 y47.5 f105 0.459    0.470    1.02   <- 목표 0.46/0.47 오차 0.001
  H520 y48 f105   0.471    0.500    1.06
```

- **크기는 `H` 로** — 기울기는 `H` 에 정확히 선형(230/345/460 에서 0.067/0.099/0.132).
- **비(앞면/옆면)는 요로만** — `H` 와 무관(y45 0.85 · y47 1.02 · y48 1.11 · y55 1.79).
  먼저 요로 비를 맞추고, 그다음 `H` 로 크기를 맞춤. 두 손잡이가 직교.
- `fov` 를 올리면 크기가 커지지만 비가 나빠짐(y45 에서 f45 0.97 → f120 0.80). `fov` 는 105 로 두고 `H` 를 씀.
- 명시 회전을 주는 순간 `perspectiveFront/Left/Right` 48·49·50 이 **셋 다 같은 값**을 냄.

⚠️ **2H 트릭은 `prstGeom` 전용.** PowerPoint 3D 는 도형틀(`ext`)이 아니라 **경로 자신의
bounding box** 를 상자로 삼음. custGeom 으로 윗절반만 그리면 기울기가 정확히 절반이 되고
밑변 V 가 되살아남. 실루엣 높이·폭은 맞게 나와서 min/max 검사로는 안 걸림 — 기울기로 판정.

⚠️ 2H 상자는 지평선 아래로 보이는높이만큼 더 나가서 **그룹 bbox 가 실제 그림보다 큼.**
「그룹을 상자에 맞춰 축소」하는 배치를 쓰면 그림이 작아짐(실측 64%). **보이는 영역을 크롭
사각형으로 명시**해서 배치.

⚠️ **앞면이 더는 무왜곡이 아님** (폭 120 → 실측 144, 위아래로 사다리꼴). 앞면 위에 평면
폴리곤으로 얹은 창·격자·라벨은 **호모그래피로 재사상해야** 함.


### ★ 단차(계단형 구멍) — 슬래브 두 장을 겹쳐 그룹으로 묶음

돌출 하나로는 부분 깊이 홈이 안 나옴. 단차는 **구멍 크기가 다른 슬래브 두 장을 위아래로 붙여** 만듦.

```
위 슬래브 : 큰 구멍   ->  안쪽 먼벽이 어두운 ⌄ 두 줄로 보인다
아래 슬래브: 작은 구멍 ->  그 윗면이 **턱**, 구멍으로 뒤가 비친다
```

어두운 ⌄ 안쪽에 윗면과 같은 색의 넓은 면이 있으면 그건 바닥이 아니라 **아래 슬래브의 윗면(턱)**.

아래 슬래브의 윗면은 모델로 유도 — 위 슬래브의 **밑면** 꼭짓점이 곧 아래 슬래브의 윗면 목표:

```python
BOT = project3d(**U, ...)[4:]          # 위 슬래브 밑면 4점
L   = solve_3d(BOT, 남은두께, square=True)
# 검산: 두 슬래브의 W 가 일치해야 한다 (실측 3.089 vs 3.093)
```

두께 배분은 **어두운 ⌄ 밴드의 세로폭**이 곧 위 슬래브 두께(실측 12 px / 전체 24 px).


### ★ 그룹 — 3D 를 유지한 채 한 단위로 묶음

COM `ShapeRange.Group()`, XML 은 `<p:grpSp>`. `com_post` 연산으로:

```python
{"slide": 1, "group": (["Ins_l", "Ins_u"], "Insulation3D")}
```

**순서: 병합 → 3D → 마지막에 그룹.** 그룹을 먼저 하면 각 도형에 3D 를 개별로 못 걺.
그룹은 각자의 3D 유지.

⚠️ **2D z-order 는 3D 깊이를 대신하지 않음.** 단차에서 `lower` 를 `upper` 보다 나중에
추가하면 단색 lower 가 구멍 뚫린 upper 를 화면에서 통째로 덮어 포켓이 안 나옴.
→ **아래 슬래브를 먼저 추가.**

⚠️ **그룹 안의 도형은 `slide.shapes` 로 안 잡힘.** 조명·색을 일괄 수정하려면
`spTree.iter(qn("a:lightRig"))` 처럼 XML 을 전수 검색.

**깊이 정렬 없음**: z-order 로 겹칠 뿐. 같은 `scene3d` 를 준 동일 도형은 위치가 달라도 투영이
완전히 같음(각 도형이 자기 중심 기준). 층마다 시점이 다른 폭발도는 층마다 따로 설정.


### ★★ `outerShdw` — 3D 에도 먹음. 쓸 자리와 못 쓸 자리 (2026-09-06 실측)

**되는 것**
- **`sp3d`/`scene3d` 를 건 도형에도 그림자가 렌더됨.** 실루엣은 2D 경로가 아니라 **3D 실루엣**을
  따름(그림자 왼끝 `3D왼끝 - dist·cos(dir)` = 122.7 예측 / 125 실측; 2D 기준이면 171).
- **`sy`/`kx`/`algn` 으로 지면 투영(원근) 그림자가 됨.** `sy=-40000, kx=-1200000, algn="bl"` →
  물체 아래로 납작한 평행사변형, 높이가 물체의 34 %, 우하로 기움. **`kx` 부호를 뒤집으면 좌우가 바뀜.**
- `dir` 은 동쪽 0, **화면 y 아래 기준 시계방향** (`dir=135` = 좌하).
- `sx`/`sy` = 1/1000 %, `kx`/`ky` = 1/60000 도. `sx/sy/kx/ky/algn` 은 `<a:outerShdw>` 에 직접 씀(스니펫에 헬퍼 없음).

**못 쓰는 세 가지**
1. **투명한 도형은 그림자를 못 드리움.** `solidFill alpha="0"` → 그림자 화소 0, `<a:noFill/>` → 0,
   불투명 → 12,295. 「보이지 않는 실루엣 운반체」 수법은 원천 봉쇄됨.
2. **겹치면 곱셈.** 알파 60 % 두 장을 흰 배경에 겹치면 255 → 102 → 41 (= 255×0.4×0.4).
   원본이 «균일한 그늘 면» 이면 이 방식으로는 재현 못 함.
3. **그림자는 자기 도형과 같이 칠해짐. 나중에 깔리는 불투명 도형이 지움.** «2점 투시 + 2H 상자»
   구조는 지면 사각형이 건물보다 나중이어야 하므로 건물에 건 그림자가 전부 지면에 덮임
   (실측: 그늘/양지 밝기비 0.967~0.987 = 그림자 없음. 폴리곤 한 장은 0.599~0.650).

**판정 기준**: `outerShdw` 는 **캐스터가 불투명하고 리시버보다 «나중에» 그려질 때만** 쓸 수 있음.
- 지면 그림자(리시버=지면이 캐스터보다 나중) → 못 씀. 폴리곤 한 장이 나음.
- **건물이 건물에 드리우는 그림자**(캐스터가 앞) → 쓸 수 있음. 2H 상자여도 문제없음.

```python
# 앞 동에 걸면 뒤 동 벽에 앉는다 (dist/dir 은 두 동의 깊이 차이라 쌍마다 다르다)
# frame 도형은 shadow.inherit=False 로 빈 <a:effectLst/> 가 이미 있다 → 그 안에 넣는다(둘이면 스키마 위반)
# S 는 모듈 전역 — set_frame() 뒤에 읽는다
from pptx.oxml import parse_xml
from pptx.oxml.ns import qn, nsdecls
ef = caster._element.spPr.find(qn('a:effectLst'))
ef.append(parse_xml(
    '<a:outerShdw %s blurRad="%d" dist="%d" dir="%d" algn="ctr" rotWithShape="0">'
    '<a:srgbClr val="0D0E0C"><a:alpha val="51000"/></a:srgbClr></a:outerShdw>'
    % (nsdecls('a'), emu(4.0 * S), emu(97.2 * S), int(148.1 * 60000))))   # blur·dist = 원본 px × S(인치) → EMU
```

- **그림자를 붙이면 그 도형의 3D 렌더가 바뀜** — 같은 상자(PresetCamera 50, fov 105, RotX 47.5, Depth PT(90))에 위 그림자를 붙이자 앞면 129×347 → 119×332 px, 윗변 y 205 → 210(원인 미상). 카메라·크기는 그림자를 붙인 상태에서 맞추거나 붙인 뒤 다시 측정.
- `dist`/`dir` 계산값이 그대로 안 나옴 — 요청 (87.5 px, 144.1°) 에 실제 (-60.8, +51.3):
  dy 는 정확한데 dx 만 10 px 짧음. 렌더에서 모서리를 재서 한 번 되먹이면 1~3 px 로 붙음.
- 알파: 받는 벽 색 `R`, 그림자 색 `C`, 목표 밝기비 `k` 면 `A = (1-k)·R̄ / (R̄ - C̄)`.
  헤이즈·그라디언트가 끼면 어긋나므로 렌더 한 번 재고 고침(46 → 0.649, 51 → 0.609).
- **원본에 없는 곳에 걸지 않음.** 「같은 벽인가」는 **창 격자가 그늘을 관통해 이어지는지**로 판정.
