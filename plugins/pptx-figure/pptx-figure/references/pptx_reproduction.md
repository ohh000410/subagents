# 재현 모드 — 원본을 재서 따라 그림

★ **창작(스펙에서 새로 그리기)이면 이 파일은 읽지 않음.** `pptx_creation.md` 로 이동.

## 1. 좌표계 — 원본 픽셀을 그대로 씀

원본 이미지 픽셀 좌표를 **유일한 진실**로 두고 슬라이드로 선형사상.

```python
FX0, FY0, FX1, FY1 = ...          # 원본에서 잰 figure 프레임
S = W_in / (FX1 - FX0)
def X(p): return (p - FX0) * S
def PT(px): return px * S * 72.0  # ★ 폰트·선굵기도 리터럴 금지, 원본 px 에서 역산
```

- **슬라이드 비율 = 원본 비율.** 16:9 에 억지로 넣으면 굵기·폰트가 연쇄로 틀어짐.
- 투고용이면 폭 = 칼럼 폭(Nature 88/180 mm) — 그러면 `PT()` 가 실제 인쇄 pt.
- 호출자가 준 crop 이 잘려 있을 수 있음. 요소가 crop 경계에 닿으면 마스터 이미지에서 측정.

## 2. 측정 방법론

### 잴 수 있으면 유도하지 않음

값을 정하는 방법은 둘뿐 — **그 값을 원본에서 뽑아낼 채널이 있는가.**
- **논증**은 잴 수 없을 때만 (예: "3D 상자인가" — 정사영·수직돌출이면 좌우 끝이 반드시 수직 변).
- **실측**은 잴 수 있으면 무조건. "꼭짓점은 모서리에 스냅하겠지"는 5 px 틀렸음(IoU 0.9718 → 실측 0.9839).

여러 에이전트가 이어받는 작업이면 인계 문서에 신뢰도 표시:
```
[확정]  원본에서 재고 렌더 되읽기 대조까지 끝남 -> 다시 재지 않는다
[실측]  쟀지만 렌더 대조 전 -> 써도 되나 검증에 포함시킨다
[추측]  렌더를 눈으로 보고 적은 것 -> 반드시 잰다
```

### 크기를 정확색 마스크로 재지 않음 — 배경이 다르면 편향됨

경계가 흐린 도형(반투명·soft edge·안티에일리어싱)의 크기를 "정확색과 일치하는 화소"로 재면
임계가 배경색에 따라 다른 피복률에서 걸림. 원본(초록 위)과 렌더(흰 위)를 같은 방법으로 재도 값이 다름.

```
                     원본(초록 위)     렌더(흰 위, 같은 크기 지정)
정확색 마스크 모멘트   61.38 x 18.87    59.42 x 18.03      <- 3.2% 편향
피복률 가중 모멘트     63.40 x 19.94    63.4  x 19.9       <- 일치
```

**중심(1차 모멘트)은 대칭이라 편향이 없음** — 위치 검증은 통과하고 크기만 조용히 틀림.

```python
c = np.clip((bg - px) / (bg - fg), 0, 1)      # 화소별 피복률 복원
m00 = c.sum(); cx = (c*X).sum()/m00           # 2차 모멘트까지 c 로 가중
```

### 2-0. 재기 전에: 이 관측이 진짜인가

- **경계 판정**: 경계 바깥 4~5px 색을 찍어 배경/다른 층/라벨 분류. 관측 가능 구간이
  절반 이하인 변은 소스 주석에 남김 — 실측과 같은 신뢰도가 아님.
- **이웃의 변이 내 변인 척함.** 전 구간 피팅 rms 가 낮아도 중간부터 다른 요소의 변일 수 있음.
  **구간별 기울기가 튀는 지점이 경계**(+0.23 vs −0.20).
- **참조값 오염**: 확정한 비율이 옆 요소 값과 소수점 셋째 자리까지 닮으면 출처가 같은 것.
  수치마다 어느 화소에서 나왔는지 주석을 남김.
- **어두운 영역이 구멍인지 아래층인지**: 안쪽 화소가 요소 자신의 색이면 포켓, 다른 색이면 관통.
- **'없다'는 내 마스크의 산물일 수 있음**: 부재를 근거로 쓰기 전에 원시 화소를 직접 찍음.
- **비교 창**: 작으면 원본이 잘려 헛짚고(bbox 차 +125px), 크면 옆 패널·옆 요소가 섞임.
  창은 요소 실루엣에 맞추고, 경계 판정은 창이 아니라 배경 예측색과의 차이로 함.

### 2-1. 꼭짓점 — 변 교점을 내지 말고 극단 열/행을 읽음

edge-on 판은 변 기울기 차가 0.2 수준이라 변 피팅 rms ≤1.7 이어도 교점이 5% 튐.
마스크의 **극단 열/행은 직접 관측**이라 안 튐.

- 후보가 둘이면 각각 `square=False` 로 돌려 **자유 종횡비가 1 에 가까운 쪽**을 채택
  (1.0020 vs 1.0507). `square=True` 비용이 싸면(+0.08px) 측정이 좋다는 증거, 비싸면(+2.5px)
  오차가 형상으로 흡수되고 있었다는 신호.
- **가려진 꼭짓점을 데이터인 척 넣지 않음.** 자유변수로 두고 조건(이웃 카메라 일치 등)을 하나 더 넣음.
- 코너 ~10px 는 라운딩으로 깎임. 코너에서 떨어진 열로 재고 코너는 외삽.
- **얇은 구조는 run guard** (연속 16px 미만 무시) — 이웃 사이 블렌드 조각이 요소로 잡힘. 스니펫 `guarded_extent()`.

### 2-2. 회전·반복·크기

- **회전된 도형은 자기 축으로 측정**: 샤프트로 축을 피팅 → 폭은 축에 수직으로.
- **반복 요소는 인스턴스마다 측정** ("대칭이니 복제"가 틀린 실측: 패널 724px vs 화살표 820px).
- **크기는 눈대중 조정 금지**: 기준 요소를 양쪽에서 재고 비율로. 폰트가 다르면 폭과 cap 높이를
  동시에 못 맞춤 — 어느 쪽을 맞출지 정하고 나머지는 한계로 보고.

### 2-3. 색·면·채움

★ **채움과 선을 둘 다 판정.** "얇은 색 띠"는 채움 있는 얇은 도형과 채움 없는 굵은 선
둘 다로 만들 수 있고 화소로는 못 가름. 실측(원작자 도형 54개): 채움+테두리 11개, 선만 1개.
채움만 보고 만들면 테두리가 통째로 빠짐.

관습: 세로 구분선·가이드는 `line`, 테두리는 `a:ln`, 면은 `fill`. 셋을 따로 확인.
XML 로 확인할 때 **채움은 `<a:spPr>` 안쪽만** 검사 — 도형 전체를 스캔하면 텍스트·선의 `solidFill` 이 섞임.

- **밝기 히스토그램의 봉우리 개수 = 면의 개수.** 사각 영역 median 은 인접 면이 섞임 — 클러스터로 분리.
- **채움 판정은 프로파일 모양으로**: `평탄`=단색 · `평탄→램프`=3-stop · `평탄→램프→평탄`=4-stop.
- **선형/방사형 = 어느 binning 이 프로파일을 조이는가**: t 로 묶어 평평한데 x·y 로는 아니면 방사형.
  선형은 `L=a·x+b·y+c` 전화소 피팅. PowerPoint 방사형은 반경 함수만 — 방위각 색조 변화는 원리상 불가.
- **'전이=양쪽 평균' 판정은 전이 폭이 업샘플 블렌드 수준(3~6px)일 때만.** 폭이 크면(65px)
  프로파일 **극대값 유무**로 가름 — 극대 있으면 별개 도형.
- **입체의 어두운 띠**: 우묵한 자리는 먼 쪽 두 벽만 어두움. 사방이 어두우면 무늬.
  ⌄ 안쪽 넓은 면은 바닥이 아니라 단차 턱(`pptx_3d_core.md`).
- 마스크 문턱값은 한 번 좁혀보고 형상이 변하는지 확인(16→12 에서 tilt 부호가 뒤집힌 실측).
  배경이 그라디언트면 상수 비교 대신 위치 보간값과 비교.
- 배경이 요소와 같은 색 계열이면 명도를 같이 걺. 흰 요소는 **중성도 `|R-B|<14`** 로.

### 2-4. 원근·모순

- 원근 투영이면 **층마다 비율이 다른 것이 정상**(bh/hw 0.084→0.224 단조 증가 실측).
  카메라는 `solve_3d` 가 역산.
- 두 실측이 모순되면 평균 내지 말고 **둘이 공유하는 가정 의심**
  (실루엣 89 vs 색 경계 112 — 틀린 건 "두께 일정" 가정이었음).

## 3. 검증 루프

**코드 → 렌더 → 이미지를 직접 확인 → 수정.** 육안 확인은 `export_png(width=1350)`, 수치 측정만 1:1.
**3D 서식은 bbox 를 안 바꾸는데 렌더는 bbox 밖으로 나감** — 3D 슬라이드는 반드시 렌더를 눈으로 확인.

### 원본 대조

- **가림이 크면 IoU 금지 — recall + '원본에만 있는 화소 %' 로 판정**
  (IoU 0.33 인데 recall 0.995 / 실루엣 4변 ≤3px 실측).
- **원본에만 있는 가림 요소(라벨·콜아웃·위층)를 재현에도 합성하고 비교** (23% 가림 실측).
  "측정상 맞다"와 "보기에 같다"가 갈리면 비교 조건부터 맞춤.
- 차분 히트맵(64×64 블록)으로 상위 블록만 크롭해 확인. crop 아티팩트를 먼저 제거.

### 알파가 위치에 따라 변하면 z-order 의심

알파는 도형의 성질이라 위치에 따라 변할 수 없음. 같은 도형인데 잰 알파가 자리마다 다르면
**위에 다른 반투명 층이 있음**. 실측: 화면 전체를 덮은 tint 가 캡슐·텍스트까지 전부 위에 얹힌
최상단이었음 — "배경처럼 보이니 맨 아래"라고 가정하지 않음. 색을 역산할 때는 위에 덮인 층을 먼저 벗김.

### 투명도는 실루엣 검사를 통과 — 별도 항목으로 측정

bbox·recall·IoU 는 전부 실루엣 지표라 투명도 무시(recall 0.97 / IoU 0.94 통과한 원반이 알파 1.0 으로 틀림).
- **판정: 서로 다른 배경 위 같은 요소의 색 비교.** 배경 하나 위에서 색이 일정한 것은 투명도에 대해 아무 증거가 아님.
- 배경 표본은 요소 바깥에서, 요소 뒤에 실제로 깔린 것을 채취(엉뚱한 y 밴드면 알파 0.652 → 0.724).
- 여러 창으로 최소자승: `obs = a·C + (1−a)·bg` 를 창 4개 이상에서 풀면 alpha 와 원색이 동시에 나옴.
- 채널별 `1−(o1−o2)/(bg1−bg2)` 가 **세 채널 일치 → 투명 / 불일치 → 불투명**.

### '원본에 있는데 재현에 없는 것'을 세는 항목을 따로 둠

파임은 실루엣을 안 바꿔 recall 로도 안 걸림(레일 편차 0.00000 통과 판에 포켓 4개 누락).
- 원본 요소 안에서 톤을 분류(`blobs()`), 옆면·안쪽 벽처럼 설명되는 것을 지우고 남는 덩어리가 빠뜨린 구조.
- "끝이 있으니 파임"은 틀린 기준 — 가림에 잘린 조각일 수 있음. **판정은 평면 좌표로**:
  덩어리 끝을 `unproject3d` 로 되돌려 전 구간이 구멍 안이면 벽, 레일로 나가면 파임.
- 재현 쪽을 셀 때 분리 띠가 화면에서 1px 넘게 넓어야 갈라짐(0.057 in 실측).

### 보정 파라미터가 0 이 아니면 상위 모델 의심

방사형 초점 0.06 이 형상을 타원 → 원으로 고치자 0 으로 돌아갔음 — 틀린 형상을 상쇄하던 값이었음.
교차검증: **기하가 맞으면 채움 프로파일이 날카로워짐**(램프 t 0.72‥0.82 → 0.79‥0.82).

### 띠·획의 형상은 중심선으로 판정

띠 전체 화소의 산포는 띠 폭에 지배됨. **각 방위각에서 띠의 중점만 뽑아** 측정(중심선 rms 2.10 vs 4.96).

### 오차가 사는 축으로 평균 내면 오차가 사라짐

**방향성 있는 모델은 그 방향으로 나눠 측정**: 방사형→방위각별(`radial_profile()`, 3개 이상),
선형→축의 수직 방향, 회전 요소→변별.

### 화면에 있는데 도형 목록에 없으면 `mc:AlternateContent` 확인

`<a:t>`·`<p:sp>` 만 훑으면 **수식·차트·SmartArt 가 통째로 안 보임**(OMML 수식 8개 실측).
**python-pptx 로 생성하는 API 가 없음.** "재현 못 함"이 아니라 "사람이 넣는 개체"로 구분해 보고.
이탤릭 수식체(𝑻·𝑃𝐶𝑀)가 보이면 의심.

### 같은 채움을 공유하며 겹치는 요소는 렌더만으로 못 가름

채움이 완전히 동일한 도형이 겹치면 분리 단서가 남지 않음(방사 배치 화살표 3개 실측 117/120/118°).
원본이 픽셀뿐이면 이 구간은 추정으로 놓고 그렇게 보고. 원작자 XML 이 있으면 `xfrm` 으로 즉시 끝남.

### 검산은 다른 경로로 함

- **XML 오독**(표기·상속·회전·flip) → **렌더로만** 반증됨.
- **화소 오독**(겹친 결과를 도형 하나의 증상으로 읽음) → **원문으로만** 반증됨.
- 원본이 픽셀뿐이면 **프로브 렌더가 유일한 두 번째 경로**.

### 화소만 보고 도달하는 정확도 — 교정값

원작자 XML 과 대조해 잰 실측(도형 54개, 4000 px 폭):
```
위치 ±5 px (0.017 in) · 크기 0.005 in · 알파 ±0.02
그라디언트 stop 색·위치는 글자 그대로 일치 · 전체 |d| 2.06 · |d|<5 가 97.4%
```
이보다 큰 오차가 남으면 측정 한계가 아니라 모델이 틀린 것.

### 측정이 서로 어긋나면

결론의 **부호**가 갈리면 스케일 차이가 아님 — 서로 다른 화소를 보고 있음.
상대 마스크를 그대로 구현해 자기 빌드에 돌려 재현되는지부터 확인. 보고는 나빠진 밴드를 먼저.
