# 창작 모드 — 스펙에서 새로 그린다

★ **원본을 따라 그리는 작업이면 이 파일이 아니라 `pptx_reproduction.md` 다.**

```
재현:  화면 꼭짓점 --> solve_3d --> 카메라·치수     (역방향)
창작:  실제 치수 + 내가 고른 카메라 --> 화면        (순방향)
```

창작은 치수를 이미 알고 카메라를 내가 고르므로 **측정이 없다.** `pptx_reproduction.md` 의
측정 방법론은 통째로 안 쓴다.

## 1. 스펙 표에서 시작한다 — 그림이 아니라 표가 원본이다

호출자에게 받아야 할 것(없으면 **묻는다**. 도식용 가정값을 만들면 반드시 산출물에 명시):

| 항목 | 예 |
|---|---|
| 층 이름 · 실제 치수 | `Acrylic 60 x 60 mm` |
| 층 두께 | `5 mm` |
| 색 | `#7ECBA1` |
| 아래층과의 간격(폭발도) | `8 mm` 또는 화면 px |
| 구멍·포켓 | 위치·크기를 **실제 치수로** |
| 용도 | 발표용 / 논문 투고용(투고면 3D·베벨·그림자 금지) |

스크립트 상단에 이 표를 **상수로** 올린다. 치수를 바꾸면 그림 전체가 따라와야 한다.

## 2. 배율 하나를 정한다

```python
S = 0.05          # in per mm  (60 mm -> 3.0 in)
W_in    = w_mm * S
Depth_pt = th_mm * S * 72          # ★ Depth 는 pt, W/H 는 in. 배율을 두 번 적용하지 마라
```

배율이 층마다 다르면 스펙이 아니라 눈대중이 된다. **하나만 쓴다.**

## 3. 카메라를 하나 고르고 전 층에 그대로 쓴다

```python
CAM = dict(PresetCamera=48, RotationX=60.0, RotationY=-40.0, RotationZ=-70.0,
           FieldOfView=45.0)        # ★ fov 는 70 미만 (pptx_3d_core.md 투영 모델)
```

각도를 렌더로 더듬지 않는다. 후보 몇 개를 `project3d` 로 **화면에 어떻게 떨어지는지
계산해서** 고른다. 렌더는 마지막에 확인용으로 한 번.

## 4. 폭발도 간격은 2D 오프셋이다 — 3D 이동이 아니다

PPT 3D 에는 **장면(scene)이 없다.** 도형마다 자기 카메라가 붙는다. 층을 위아래로
벌리는 것은 각 도형의 **중심 좌표 `cy` 를 옮기는 것**이지 z 를 주는 게 아니다.

```python
cy = CY0 - sum(gap_in[:i])         # 위로 갈수록 화면에서 위
sh.add_shape(RECT, emu(cx - W/2), emu(cy - H/2), emu(W), emu(H))
```

`project3d(...)` 로 각 층의 실루엣을 **미리 계산해** 겹침·간격을 확인한다.

## 층마다 원근을 줄 것인가

모든 층에 같은 카메라를 주면 같은 크기의 판이 화면에서도 같은 크기로 나온다.
정사영 폭발도처럼 보이고, 논문 figure 로 흔하다. **기본은 이쪽.**

실제 원근 장면이라면 아래 층일수록 면이 더 벌어진다(재현 원본 실측 bh/hw
0.084 → 0.171 → 0.211 → 0.224 단조 증가). 그 느낌이 필요하면 층마다 `RotationX` 를
**단조 규칙**으로 조금씩 준다(예: 위 58도 → 아래 66도). 규칙을 스크립트에 상수로 남기고
**어느 쪽을 썼는지 보고에 명시한다.**

## 5. 형상 만들기

- 판 = 사각형 + `sp3d`. 두께 없는 시트도 **`Depth = 0` 네이티브 3D**(폴리곤 금지).
- 구멍 = Merge `Subtract`. 색으로 덮는 것과 다르다 — `pptx_3d_core.md`.
- 단차·포켓 = **슬래브 두 장 + 그룹.** **아래 슬래브를 먼저 추가한다.**
- 아래 슬래브의 윗면은 위 슬래브 밑면에서 `project3d(...)[4:]` 로 유도한다.
  평행이동으로 놓지 않는다 — 실측 y 오프셋이 꼭짓점마다 24~35 px 로 벌어진다.
- 조명 `rig` 은 카메라마다 승자가 다르다. 카메라를 정했으면 rig 도 한 번만
  프로브해서 전 층에 같은 것을 쓴다.

## 6. 검증 — 원본이 없으므로 스펙이 정답이다

| 대상 | 판정 |
|---|---|
| 치수 | COM 되읽기 `Width/Height/ThreeD.Depth` 를 스펙과 대조. 계산을 다시 하는 건 대조가 아니다 |
| 카메라 | 전 층의 `RotationX/Y/Z·FieldOfView` 가 전부 같은가(또는 정한 단조 규칙대로인가) |
| 비율 | 두 층의 화면 폭 비 = 스펙 치수 비인가. 어긋나면 배율을 두 번 먹인 것이다 |
| 층 간격·겹침 | `project3d` 예측과 렌더 실측이 맞는가 |
| 형상 | **렌더를 Read 로 직접 본다.** 3D 는 bbox 가 안 변하므로 육안 확인이 필수다 |

## 7. 참고 이미지는 기하가 아니라 스타일에만 쓴다

인터넷 그림·논문 figure 는 색 팔레트, 라벨 배치, 시점 선택, 폭발 간격 관행을 보는 데 쓴다.
**여러 그림에서 기하를 조합하지 않는다** — 각 그림이 다른 카메라라 층마다 시점이 어긋난다.
참고 그림을 봤으면 스펙 표의 숫자로 환산해서 쓴다.
