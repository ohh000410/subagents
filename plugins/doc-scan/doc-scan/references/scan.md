# scan.py — 처리 단계와 근거

```bash
T="<PLUGIN_ROOT>/doc-scan/tools"
"$T/.venv/Scripts/python.exe" "$T/scan.py" <사진|폴더> [...] [--out 폴더] [--mode color,gray,bw] [--pdf 이름.pdf] [--no-crop]
```

## 단계

| 단계 | 방법 | 근거·실측 |
|---|---|---|
| 열기 | PIL + `ImageOps.exif_transpose`(휴대폰 회전), `pillow-heif`(아이폰 HEIC) | — |
| 종이 찾기 | 긴 변 1000 px 로 줄임 → 흐림 → 닫힘 연산(글자 지우기) → 후보 두 갈래 ① Canny(문턱 = 중앙 밝기 × 0.67/1.33) ② Otsu 밝은 덩어리 → 볼록 껍질 → 꼭짓점 4개 근사. 조건: 사진 면적 20% 이상, 내각 최대-최소 40° 미만. 가장 큰 것 | 내각 조건·면적 조건: andrewdcampbell/OpenCV-Document-Scanner(면적 25%, 280장 중 92.8% 검출). 자동 문턱: AVI20953/doc-scan. ② 는 2026-10-08 시험에서 기울인 사진의 그림자 쪽 테두리가 끊겨 ① 만으로 실패해 추가 |
| 펴기 | 꼭짓점 정렬(왼위·오위·오아래·왼아래) → 원근 변환. 출력 크기: 가로 = 긴 위/아래 변, 세로 = 가로 ÷ **실제 비율** | 변 길이 비만 쓰면 비스듬한 사진에서 비율이 틀린다(시험: A4 0.707 → 0.82). 실제 비율은 꼭짓점으로 초점거리와 함께 구한다 — Zhang & He, "Whiteboard scanning and image enhancement", Digital Signal Processing 17(2), 2007. 사진 중심 = 렌즈 중심, 정사각 화소 가정. 풀이가 안 되면(f² ≤ 0, 거의 정면) 변 길이 비 |
| 조명 보정 | 채널마다 배경 추정(7×7 팽창 → 중앙값 흐림, 커널 = 짧은 변/40) 으로 나눈 뒤 0~255 정규화 | 그림자·손 그림자·조명 기울기 제거 |
| 흑백 | 보정한 회색조에 적응형 문턱(가우스, 블록 = 짧은 변/30, C = 10) | — |
| 저장 | `cv2.imencode` → `write_bytes` | `cv2.imwrite` 는 Windows 에서 한글 경로를 못 쓴다 |

## 시험 기록 (2026-10-08, 합성 사진)

A4(1240×1754) 한글 문서를 3D 로 돌려 실제 카메라 모형(f = 3200 px, 사진 3000×4000, 중심 = 사진 중심)으로 찍고 갈색 책상·대각 조명 기울기·손 그림자를 넣었다.

| 사진 | 종이 면적 | 검출 | 결과 비율(A4 0.707) |
|---|---|---|---|
| 정면(3°, −2°) | 59% | ○ | 0.708 |
| 비스듬(25°, −12°) | 51% | ○ (①실패 ②성공) | 0.690 |
| 많이 기울임(35°, 18°) | 42% | ○ | 0.715 |
| 종이가 작음(12%) | 12% | × (면적 조건) | — |

- 정면이 아닌 두 장은 종이 모서리 하나가 사진 밖이었다 → `corner_at_photo_edge` 로 알린다.
- 첫 시험은 꼭짓점을 임의로 정한 합성(실제 카메라로 불가능한 원근)이라 비율이 0.643 으로 나왔다 — 비율 계산을 시험하려면 카메라 모형으로 만든 사진을 쓴다.

## 한계 (확인된 것만)

- 휜 종이(책 가운데, 구겨짐)는 사각형으로만 펴서 곡면은 남는다.
- 흰 책상 위 흰 종이처럼 배경과 밝기 차가 작으면 ② 가 안 되고 ① 에만 의존한다(시험 안 함).
- 실제 휴대폰 사진으로는 아직 시험하지 않았다 — 첫 실사용 결과를 memory 에 남긴다.
